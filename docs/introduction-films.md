## 實際畫面與可編輯來源

Kinesmith 片實際使用 Canvas、Rough.js 與 Three.js；其中 Three.js 原生金屬環、光線、材質及相機逐格渲染。影片介紹 p5.js、Manim 與 Blender 的適用能力，但沒有把本片畫面冒稱為這三種引擎產生；原有六引擎範例仍可獨立驗證。

Codex 片使用原生 Canvas，包含程式差異、執行／觀察／修正循環、工作視窗與 Skills。這些為原創圖形示意，並非 Codex 操作錄影；有清楚的「示意」及「非 OpenAI 官方影片」標記。產品事實依作品 `sources.md` 的 OpenAI 官方文件查核，未承諾特定帳號方案或價格。

`examples/introductions/` 保存原始需求、Motion Brief、兩個 project JSON、原生 HTML／JS、字型與 OFL、獨立配樂 WAV、MIDI、完整音符事件、合成程式、Cue Sheet、SRT、修訂歷史與重現方法。全片依整數影格渲染，沒有以即時播放速度錄影。

## 客觀檢查

- 兩片各自完整解碼所有音畫串流，實測 1440 影格、48 秒、1080p／30fps，無解碼錯誤。
- 每個正式影格都有文字邊界診斷，最終兩片均為空清單；Canvas 診斷使用實際字型度量與當下座標轉換。
- 一般亮度 heuristic 未發現全黑區間。章節間的深／淺色硬切會產生亮度差候選，是分鏡刻意安排，保留原始旗標。
- 閱讀停留與結尾定格被低解析度 heuristic 標示為 possible_freeze；這不代表錯誤，也不將這個旗標自動當成「未跳格」的證明。
- 正式時間軸 0、6、12、18、24、30、36、42、46 秒的音符事件皆與指定影格一致。另將 MP4 解碼後的音訊與原始 WAV 片段做波形相關比對，兩片 9 個 Cue 的對齊誤差均為 0 個樣本，容許值為 1 影格。這是已知原創配樂的對齊，不是人聲／音素辨識。
- 每支配樂的母帶與編碼後解碼皆為 2,304,000 個 48kHz 立體聲樣本，與 48 秒相符。

## 視覺抽查與修訂

已直接檢視兩片關鍵影格 Contact Sheet、完整成片 Contact Sheet，以及 7 個切點的連續影格 Contact Sheet。抽查可見繁體中文字型正確、文字完整、Three.js 空間主體及片尾卡完整；深淺色切換符合章節設計。

34.9 秒的 Kinesmith v1 影格曾出現協作鏡頭字幕與外圓環相交。修訂 2 使用 `kinesmith revise` 只分叉 `kinesmith-06`，將字幕下移並增加按鈕留白。重新渲染後已檢視同時間的 1080p 影格，字幕與圓環有間距。其他七幕全部 1260 張原生影格雜湊與修訂前完全相同、全部使用原有快取；配樂原檔未變。`local-revision.json` 保存逐幕結果，專案 `history/` 保存 v1 時間軸與來源。

已做的是代表影格及連續切點影格抽查；沒有宣稱完整連續觀賞、主觀試聽、所有裝置顯示或跨 GPU 像素完全一致。響度、峰值與波形同步不能證明音樂的主觀美感。這兩片沒有製作人聲旁白。

原創圖形與程式 MIT，兩部配樂、音符與 MIDI 為 CC0-1.0；Noto Sans TC 原字型為 OFL-1.1，已內附完整聲明，並在 project dependencies 記錄。Rough.js、Three.js、FFmpeg 及其編碼器依本專案第三方聲明；作品包不重包這些執行檔。
